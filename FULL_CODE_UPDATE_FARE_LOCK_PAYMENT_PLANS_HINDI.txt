HimRideG — FINAL FARE LOCK + PAYMENT PLANS UPDATE
=================================================

FULL CODE RULE
--------------
Yeh full-project replacement package previous HimRideG HMG Waiting-for-Payment
project ko base rakhkar banaya gaya hai. Existing project files/features ko
preserve kiya gaya hai. Canonical deploy source client/ + server/ hi hai.

FINAL FLOW
----------
1. Incoming ride par Driver Accept / Reject kar sakta hai.
2. Fare negotiation / final fare bhejne wale controls fare lock tak usable rahte
   hain, kyunki inhi se final fare lock possible hota hai.
3. Final Fare LOCK hone se pehle assigned ride ke progression actions locked:
   - Navigate Pickup / Destination
   - Go to Pickup
   - I Have Arrived
   - Enter Customer OTP
   - Start Ride (backend guard)
   - Complete Ride
   - Cancel / Release UI action
4. Customer final fare accept karta hai to Customer aur Driver dono screen par
   payment popup/status page open hota hai.
5. Customer payment plans:
   A) Payment Online
      - Ride complete hone ke baad Online/UPI ya Cash option.
   B) Payment Advance
      - Full locked fare ride pickup se pehle online Pay Now.
      - Advance payment paid hone tak Driver ride progression actions locked.
   C) Scheduled Payment
      - Payment ride/travel date ke liye scheduled rahegi.
      - Pay Now button hamesha available hai.
6. Physical ride complete ho aur payment unpaid ho to UI status:
   WAITING FOR PAYMENT.
7. Payment paid/confirmed hone ke baad Completed/payment-paid state show hoti hai
   aur existing settlement/wallet logic execute hota hai.

SECURITY / BACKEND ENFORCEMENT
------------------------------
Frontend buttons sirf visual lock nahi hain. Backend me bhi fare lock validate
hota hai before pickup/arrival/start, aur Advance plan me paid status required
hota hai. Isse direct API call se UI lock bypass nahi ho sakta.

PAYMENT EVENTS
--------------
Payment plan/method/completion Socket.IO events Customer aur Driver user rooms me
sync hote hain. Razorpay verification aur webhook payment capture completion
update emit karte hain.

IMPORTANT SEMANTICS
-------------------
- "Payment Advance" currently FULL locked fare advance hai; partial percentage
  advance nahi.
- "Scheduled Payment" ka schedule existing booking travelDate se derive hota hai.
- Apple/Google/Auth, map, admin, driver-document sync, booking/fare negotiation,
  Razorpay/cash settlement aur existing routes preserve kiye gaye hain.
